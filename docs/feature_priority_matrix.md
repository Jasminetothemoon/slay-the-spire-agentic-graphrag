# 功能优先级矩阵

## 评估方法

每个功能按四个维度评估：

- **用户价值**：是否解决高频、高痛、关键决策。
- **求职价值**：是否能展示 AI 应用开发或 AI 产品经理能力。
- **实现成本**：数据、Mod、后端、UI、测试复杂度。
- **风险**：是否容易导致崩溃、误导推荐或维护困难。

评分：

- 用户价值：1 到 5，越高越重要。
- 求职价值：1 到 5，越高越适合写简历。
- 成本：1 到 5，越高越难。
- 风险：1 到 5，越高越容易出问题。

综合建议：

```text
优先分 = 用户价值 + 求职价值 - 0.6 * 成本 - 0.4 * 风险
```

该公式不是绝对标准，只用于帮助排序。

## P0：当前应该优先打磨

### 1. 真实 payload 扩展与 replay fixtures

原因：

- 这是从 Demo 到真实应用的分水岭。
- 能直接解决“游戏里不准但脚本通过”的问题。
- 对 AI 应用开发简历价值最高。

验收：

- 采集 5 到 10 局真实 JSONL。
- 每局至少覆盖卡牌奖励、遗物、商店、战斗。
- 将高价值失败 case 转为 regression fixtures。

### 2. Baseline/Ablation 报告

原因：

- 面试官会问 GraphRAG、Agent、流派规则到底有没有用。
- 报告能证明模块贡献，而不是只堆术语。

验收：

- 对比 Tier baseline、Rule baseline、GraphRAG + scoring、GraphRAG + archetype。
- 输出 Top-1、Top-3、P95、低区分度比例。

### 3. Agent trace audit 案例

原因：

- 直接回应“多 Agent 协作怎么实现”。
- 让每个 Agent 的职责和失败模式可展示。

验收：

- 至少 5 个典型 case：
  - 卡牌奖励。
  - Boss 遗物。
  - 商店删牌。
  - 战斗建议。
  - 推荐失败或低置信度。

## P1：近期增强

### 商店结构化建议

重点：

- 买不起的商品不能 Top-1。
- 删除卡要作为明确 action。
- 药水槽、金币剩余、后续商店机会成本要进入评分。

### Boss 遗物副作用建模

重点：

- 能量收益。
- 抽牌能力。
- 高费卡比例。
- 副作用承受能力。
- 当前角色和流派。

### 用户反馈闭环

重点：

- 玩家可以记录“推荐有用/无用”。
- 保存实际选择和推荐差异。
- 失败 case 自动进入 replay 候选。

## P2：中期增强

### 地图路线 lookahead

价值很高，但当前风险也高。建议先通过 fixtures 和 replay 稳定算法，再恢复 Java Mod live capture。

要求：

- 3 到 5 层路线摘要。
- 精英、火堆、商店、宝箱、问号数量。
- forced elite、rest before elite。
- 根据 HP、药水、卡组强度调节风险。

### Run history

价值：

- 支持个性化推荐。
- 支持产品指标。
- 支持“AI Coach”总结。

成本：

- 需要保存每局选择、结果、最终胜负。
- 需要数据隐私与本地存储策略。

## P3：暂缓

### 百科/知识库浏览器

原因：

- 竞品和 Wiki 已经很多。
- 它不能解决最核心的游戏内决策痛点。
- 对 AI 应用开发和 AI 产品经理简历的边际收益低于 Harness、真实 payload 和反馈闭环。

### 实时 LLM 决策

原因：

- 延迟和成本不可控。
- 推荐稳定性差。
- 很难回归测试。

更好的做法：

- 保持 deterministic scoring。
- LLM 只做异步解释、失败案例总结和社区攻略结构化。

## 推荐实施顺序

1. 完成产品文档包。
2. 采集真实 payload。
3. 扩展 replay fixtures。
4. 产出 baseline/ablation 报告。
5. 产出 agent trace audit。
6. 增强商店和 Boss 遗物。
7. 加 CI。
8. 做用户反馈闭环。
9. 稳定后恢复地图路线 live capture。

## 简历呈现建议

AI 应用开发：

> 通过真实 Mod payload replay、消融实验和 latency harness 建立推荐系统评测闭环，验证 GraphRAG、流派规则、风险评估和 CriticAgent 对推荐质量与稳定性的贡献。

AI 产品经理：

> 基于竞品与用户旅程拆解，将功能按用户价值、实现成本和技术风险排序，明确 Mod-first MVP、核心指标与后续路线图。
