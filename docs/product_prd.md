# 产品需求文档：Slay the Spire 游戏内 AI 决策助手

## 1. 产品定位

本产品是一个面向《杀戮尖塔 1》的游戏内 AI 决策助手。它不是网页攻略站，也不是单纯的卡牌百科，而是在玩家真实游戏流程中自动读取当前局面，并在游戏内直接给出可解释的卡牌、遗物、商店、战斗和营火建议。

面向求职叙事时，它对应两个方向：

- **AI 应用开发**：展示实时状态接入、多 Agent 工作流、GraphRAG、低延迟推荐、回放评测和可观测性。
- **AI 产品经理**：展示用户痛点识别、竞品拆解、MVP 定义、指标体系和 AI 推荐质量闭环。

## 2. 背景与问题

《杀戮尖塔》决策复杂，玩家经常需要同时考虑：

- 当前卡组结构。
- 遗物、药水、金币、血量。
- 当前 Act、下一场战斗风险、Boss 风险。
- 候选卡牌/遗物/商店商品的机会成本。
- 当前想走的流派和实际已经成型的方向。

传统解决方案包括查 Wiki、看攻略、打开网页工具、参考 tier list 或使用 run companion。核心痛点是：

- **切屏成本高**：游戏中频繁切到网页破坏体验。
- **泛化建议不准**：tier list 不能处理当前局面和流派差异。
- **解释不足**：只给分数无法帮助玩家学习。
- **失败不可见**：推荐不对时，用户不知道是状态读取、规则、检索还是 UI 匹配出了问题。
- **无法闭环**：玩家觉得“不准”时，开发者很难复现当时局面。

## 3. 目标用户

### 核心用户

- 熟悉基础规则，希望提高胜率和学习构筑思路的进阶玩家。
- 想在游戏内获得即时建议，但不想频繁查网页的玩家。
- 希望根据目标流派获得更有方向性推荐的玩家。

### 次级用户

- 研究 AI Agent/RAG/推荐系统的开发者。
- AI 应用或 AI 产品岗位面试官，用于评估项目工程与产品完整度。

## 4. 产品目标

### 用户目标

- 玩家启动游戏后，无需打开网页即可看到推荐。
- 推荐要能说明“为什么选它”和“为什么不选其他项”。
- 玩家可以切换目标流派，让系统推荐更符合当前意图。
- 推荐失败时，玩家能看到明确原因，而不是静默失效。

### 业务/作品目标

- 让项目从“技术 Demo”变成真实可用的 AI 应用。
- 形成可展示的 Mod-first 产品体验。
- 用评测、回放和指标证明推荐质量。
- 同时支撑 AI 应用开发和 AI 产品经理两个求职方向。

## 5. 非目标范围

当前阶段不做：

- 完整百科站或攻略站。
- 对游戏进行自动操作或托管游玩。
- 实时链路依赖外部 LLM 做核心决策。
- 深层战斗求解器。
- 多人在线服务或云端账号系统。

这些能力可以作为后续版本，但不应影响当前 MVP 的稳定性。

## 6. MVP 范围

### P0 必须有

- 游戏内推荐面板。
- F8 显示/隐藏推荐。
- F9 Debug 面板。
- F10 中英文切换。
- F11 目标流派切换。
- 卡牌奖励推荐。
- 遗物/Boss 遗物推荐。
- 商店建议。
- 基础战斗建议。
- 后端 `/mod/state` 与 `/mod/recommend`。
- 推荐结构化输出：分数、等级、理由、风险、why_not、证据。
- JSONL capture/replay。
- Eval/Ablation/Latency harness。

### P1 近期增强

- 真实 payload 扩展到 5 到 10 局完整游戏。
- 人工标注评测集扩展到 100+。
- 商店逻辑进一步考虑价格、删牌、药水槽和金币机会成本。
- Boss 遗物逻辑进一步考虑能量需求和副作用。
- Agent trace audit 文档。
- GitHub Actions CI。

### P2 后续增强

- 事件助手。
- 地图 3 到 5 层 lookahead。
- 用户反馈按钮。
- 个人 run history。
- 异步 LLM 解释增强。
- 社区策略规则自动导入与审核。

## 7. 核心用户故事

- 作为玩家，我希望在奖励界面看到每张卡牌的评分和理由，这样我不需要切网页查攻略。
- 作为玩家，我希望能选择目标流派，比如毒流、力量流、冰球流，这样推荐不会只按泛用强度排序。
- 作为玩家，我希望看到为什么不选其他卡，这样我能学习机会成本。
- 作为玩家，我希望推荐框长驻直到场景切换，这样我不用担心错过建议。
- 作为开发者，我希望真实游戏 payload 能被保存和 replay，这样我能复现现场问题。
- 作为产品负责人，我希望能看到推荐延迟、无推荐率、低区分度比例和用户反馈，这样我能判断下一步优化优先级。

## 8. 功能需求

### 8.1 游戏内 Overlay

要求：

- 推荐框默认显示当前场景、Top 推荐、等级、分数、主要理由和主要风险。
- 推荐框在同一场景中保持长驻，直到场景变化或玩家手动隐藏。
- Debug 面板显示 API 状态、scene、query_type、selected_skill、agent_trace、critic warnings、最近错误。
- 候选项旁显示 `A 84` 这类短 Badge。
- Hover 展示分数拆解、why_not、证据和风险。

验收：

- 不打开网页也能完成核心使用。
- API 关闭时显示连接失败原因。
- 旧战斗推荐不得残留到奖励、商店或 Boss 遗物界面。

### 8.2 目标流派

要求：

- F11 循环当前职业可用流派。
- 推荐评分考虑目标流派，但不能无条件牺牲当前生存风险。
- 输出中显示当前目标流派。
- 目标流派可中途切换。

验收：

- 同一个候选项在不同目标流派下分数会合理变化。
- Debug 中能看到 target_archetype。

### 8.3 推荐服务

要求：

- 接口返回 `scene_type`、`selected_skill`、`option_scores`、`agent_trace`、`critic_warnings`。
- 实时链路不依赖外部 LLM。
- Neo4j 不可用时使用本地 JSON fallback。
- 所有实体使用稳定英文 id，中文/英文名称作为展示字段。

验收：

- 本地 P95 延迟保持毫秒级到 500ms 内。
- LLM 不可用不影响推荐。
- 数据来源、置信度和关系 provenance 可追踪。

### 8.4 Replay 与评测

要求：

- Mod 可采集真实 payload 到 JSONL。
- Replay script 能逐条复现推荐。
- Harness 支持 eval、replay、ablation、latency。
- 报告输出 Top-1、Top-3、P95、无推荐率、低区分度比例、critic warning rate。

验收：

- 每个真实 bug 至少能对应一个 replay case。
- README 中指标来自可运行脚本，而不是手写估计。

## 9. 成功指标

| 类别 | 指标 | MVP 目标 |
| --- | --- | --- |
| 连接 | API 首次连接成功率 | 95%+ |
| 实时性 | 推荐 P95 延迟 | 500ms 内 |
| 覆盖 | 核心场景无推荐率 | 低于 10% |
| 质量 | 固定 case Top-3 | 80%+，当前 curated set 已更高 |
| 可观测 | 错误原因可见率 | 95%+ |
| 体验 | 推荐框稳定性 | 同场景长驻，不串场景 |
| 迭代 | 真实 payload replay 覆盖 | 5 到 10 局起步 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 游戏状态采集不稳定 | 推荐错场景或崩溃 | Debug 面板、JSONL capture、replay regression |
| 推荐不符合高手思路 | 用户信任下降 | 增加目标流派、社区策略、人工标注和 ablation |
| 地图 live capture 不稳定 | 影响路线建议 | 保守关闭 live 地图，先保留后端 harness |
| 文本过长影响 UI | 游戏内不可读 | 中英文切换、短 Badge、hover 详情、换行和截断 |
| LLM 延迟高 | 游戏体验差 | 实时链路不用 LLM，解释异步可选 |
| 数据来源混乱 | 无法解释和维护 | source_url、confidence、source_type、provenance |

## 11. Roadmap

### V0：已完成基础

- Mod bridge。
- 游戏内推荐面板。
- 双语与目标流派。
- Multi-Agent workflow。
- Decision Skills。
- GraphRAG + fallback。
- Replay/eval/ablation/latency harness。

### V1：求职展示强化

- PRD、用户旅程、竞品分析、指标文档。
- Agent trace audit。
- 真实 payload 扩展。
- Baseline/ablation 报告。
- CI smoke test。

### V2：产品体验强化

- 更稳定的商店/Boss 遗物/营火建议。
- 游戏内用户反馈。
- 个人 run history。
- 配置页。

### V3：策略质量强化

- 200+ 人工标注局面。
- 更多社区策略规则。
- 事件助手。
- 地图 lookahead 重新接入。
- 异步 LLM 策略解释。

## 12. 面试可讲结论

这个 PRD 的核心价值是说明：项目不是“我想试试 Agent”，而是从用户真实流程出发，把网页 Demo 改成游戏内 Mod；再围绕推荐质量、实时性、失败可见性和评测闭环设计产品。这种叙事更适合 AI 产品经理，也能反向增强 AI 应用开发方向的说服力。
